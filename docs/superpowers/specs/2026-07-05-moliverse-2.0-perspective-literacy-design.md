# MoliVerse 2.0 — Perspective Literacy MVP

**Date:** 2026-07-05
**Status:** Approved design, ready for implementation planning
**Event:** UNESCO Youth / Media & Information Literacy Hackathon 2026

---

## 1. Mission & Core Problem

**Mission:** Build *Perspective Literacy* for the AI generation.

> Perspective Literacy is the ability to recognize, compare, and understand how culture, history, politics, language, and media systems shape the way information is presented.

**The one problem we solve:** Young people increasingly consume information from only one perspective. MoliVerse does **not** tell users who is right. It shows them *why different media tell the same story differently* — and empowers them to think for themselves.

**The governing test for every feature (now and future):**
> *Does this feature help users understand why different perspectives exist?*
> If no, it does not ship.

This is a full pivot away from MoliVerse 1.0 (language lessons, vocabulary, grammar, exercises, quizzes, flashcards, mentor mode). All of that is removed.

---

## 2. The Core Loop (the entire product)

A single, focused journey:

1. **Search / choose an event** →
2. **Compare headlines** across countries/outlets →
3. **AI explains WHY** the framing differs →
4. **Verified background facts** (the shared floor) →
5. **Reflection questions** (think for yourself)

Nothing else. No vocabulary, grammar, exercises, quizzes, flashcards, translation, or mentor mode.

## 4. Visual Design — Editorial Newsprint

- **Palette:** paper `#f5f1e8`, ink `#1a1a1a`, red accent `#c0392b`, verified-green `#1a7a4a`; per-source top-border accent colours (e.g. `#c0392b`, `#2471a3`, `#7d3c98`, `#b9770e`).
- **Type:** serif (Georgia / a serif webfont) for headlines and body; system sans only for "chips"/labels and contested-word tags.
- **Motifs:** masthead with rule line, uppercase letter-spaced kickers ("EVENT DOSSIER"), two-column newsprint flow for the "why" section, pull-quote styling for reflections.
- **Tone:** a newsroom *investigation into the news itself*.

The approved mockups live in `.superpowers/brainstorm/**/content/` (`visual-direction.html`, `event-page.html`) for reference.

## 5. Pages

### 5.1 Landing — `app/page.tsx`
- **Masthead** (MoliVerse · The Perspective Desk).
- **Hero:** short mission line + a search box ("Search any world event…").
  - Search **filters the curated events client-side** (case-insensitive match on title, aliases, category, source names).
  - A few suggestion chips (the event titles).
- **"— or explore —" gallery:** the curated events as **dossier cards** (`EventCard`) in a grid. Each card: kicker (category · date), title, one-line subtitle, the contested-word chips as a teaser, source flags.
- **No-match state:** if a search matches nothing, show the full gallery with a gentle "We don't have a dossier for that yet — explore these" note. Never a dead end.
- A brief "What is Perspective Literacy?" strip at the bottom (one paragraph + the governing test).

### 5.2 Event Page — `app/event/[slug]/page.tsx`
Statically generated via `generateStaticParams()` from the curated events. One long editorial scroll:

1. **Masthead + event title block** — kicker (Event Dossier · date), title, italic standfirst.
2. **① The same event, N headlines** — `SourceHeadline` cards, one per source, headline shown verbatim with contested words highlighted inline; each card shows outlet, country/flag, and **orientation label**.
3. **Contested-word strip** ("One act. N names.") — `ContestedWordStrip`, dark band with the framing words as coloured tags. The dramatic centrepiece.
4. **② Why the words differ** — `FramingExplainer`, two-column newsprint; one short passage per contested term, plus a compact **historical context** note.
5. **③ What everyone agrees on** — `BackgroundFacts`: verified fact bullets + a small **`FactTimeline`** of dated events. Green "shared floor" styling.
6. **Missing perspectives** — a short "What's left out" note (whose voice is absent across all coverage).
7. **④ Think for yourself** — `ReflectionPrompts`: reflection questions as pull-quotes, each with an optional answer box saved to `localStorage` (keyed by event slug + question index).
8. **Footer nav** — back to gallery / next dossier.

## 6. Data Model

Curated events live in `lib/events/` (one file per event exporting a typed object, aggregated in `lib/events/index.ts`). Types in `lib/types.ts` (rewritten).

```ts
type Orientation =
  | "Public broadcaster" | "State-owned" | "Private / commercial"
  | "Left-leaning" | "Right-leaning" | "Centrist" | "Pan-Arab" | "Other";

interface Source {
  outlet: string;          // "BBC"
  country: string;         // "United Kingdom"
  flag: string;            // "🇬🇧"
  orientation: Orientation;// "Public broadcaster"
  accent: string;          // hex accent for the card top-border
  headline: string;        // verbatim archived headline
  contestedWords: string[];// substrings within `headline` to highlight
  framingWord: string;     // the single word for the contested strip ("invasion")
  tone: string;            // "Alarmed" | "Justifying" | "Detached" …
  focus: string;           // what this outlet emphasises (one phrase)
}

interface ContestedTerm {  // powers the strip + the "why" section
  term: string;            // "invasion"
  accent: string;          // matches the source
  why: string;             // 1–2 sentences: why this outlet chose this word
}

interface TimelineEntry { date: string; label: string; }

interface Event {
  slug: string;            // "russia-ukraine-2022"
  title: string;           // "Russia & Ukraine"
  aliases: string[];       // ["ukraine","russia","war"] for search
  category: string;        // "War & Conflict"
  date: string;            // "February 2022"
  standfirst: string;      // italic one-liner
  summary: string;         // gallery-card subtitle
  sources: Source[];       // 4 per event
  contestedTerms: ContestedTerm[];
  historicalContext: string;
  backgroundFacts: string[];   // verified, source-neutral
  timeline: TimelineEntry[];
  missingPerspectives: string; // whose voice is absent
  reflectionQuestions: string[];
}
```

**Data-integrity rules:**
- Every `contestedWords` entry must be an exact substring of its `headline` (so highlighting can't silently fail).
- Every `Source.framingWord` should correspond to a `ContestedTerm.term`.
- Background facts must be genuinely source-neutral (the "shared floor"); framing/opinion belongs in `contestedTerms.why`, not here.
- Headlines are real/archived; keep a short source attribution comment in the data file.

## 7. Components (`components/`)

| Component | Responsibility | Depends on |
| --- | --- | --- |
| `Masthead` | Newsprint header/rule line | — |
| `EventCard` | Gallery dossier card | `Event` |
| `SearchGallery` | Client component: search box + filtered gallery | `Event[]`, `EventCard` |
| `SourceHeadline` | One source's headline card with inline highlighting + orientation | `Source` |
| `ContestedWordStrip` | Dark "one act, N names" band of framing tags | `ContestedTerm[]` |
| `FramingExplainer` | Two-column "why the words differ" + historical context | `ContestedTerm[]`, `historicalContext` |
| `BackgroundFacts` | Verified facts list + `FactTimeline` | `string[]`, `TimelineEntry[]` |
| `FactTimeline` | Small horizontal dated timeline | `TimelineEntry[]` |
| `ReflectionPrompts` | Pull-quote questions + localStorage answer boxes (client) | `string[]`, slug |
| `Highlight` | Utility: renders text with given substrings marked | text, substrings |

Server components by default; only `SearchGallery` and `ReflectionPrompts` are client components (`"use client"`).

---

## 8. Data Flow

- All content is **static typed data** → pages are statically rendered. No runtime data fetching, no `/api` routes, no external network calls.
- **Search** is pure client-side filtering over the in-bundle event list.
- **Reflection answers** persist to `localStorage` only (no server). Key: `moliverse:reflection:<slug>:<index>`.

---

## 9. Error / Edge Handling

- **Unknown event slug** → Next.js `notFound()` (404) with a link back to the gallery.
- **Empty search** → show full gallery.
- **No search match** → full gallery + gentle "not yet" note.
- **`localStorage` unavailable** (SSR / privacy mode) → reflection boxes still render and function in-session; persistence silently degrades (guard all access).
- **Highlight substring not found** → render the plain text unchanged (never throw); a dev-time console warning is acceptable.

---

## 10. Testing

Lightweight, matched to a static hackathon app:
- **Data validation** (the highest-value test): a script/test asserting the data-integrity rules in §6 for every event — contested words are real substrings, framing words map to contested terms, every event has ≥2 sources, non-empty facts/reflections. Fail the build if violated.
- **`Highlight` unit test** — correct marking, and graceful pass-through when a substring is absent.
- **Search filter unit test** — matches on title/alias/category, case-insensitive; empty query returns all.
- **Manual smoke pass** — landing search, open each of the 3 dossiers, verify scroll sections render and reflection answers persist across reload.

Testing framework: add a minimal runner (e.g. `vitest`) since the project currently has none; keep it to the checks above.

---

## 11. Out of Scope (explicitly, for MVP)

Live news fetching, any LLM/AI call, user-submitted articles/URLs, bias/emotion auto-analysis, classroom/teacher mode, accounts/auth, translation, vocabulary/grammar/exercises/quizzes/flashcards, more than 3 events. These belong to the V2/V3 roadmap below.

## 12. Roadmap (context only — not built now)
