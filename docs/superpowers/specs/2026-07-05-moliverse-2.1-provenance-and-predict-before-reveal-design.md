# MoliVerse 2.1 — Provenance & Predict-Before-Reveal

**Date:** 2026-07-05
**Status:** Approved design, ready for implementation planning
**Builds on:** `2026-07-05-moliverse-2.0-perspective-literacy-design.md` (the shipped 2.0 MVP)
**Event:** UNESCO Youth Media & Information Literacy (MIL) Hackathon 2026

---

## 1. Why This Iteration

MoliVerse 2.0 shipped as a clean, coherent **read-and-reflect** scroll: hand-typed archived
headlines → framing explanations → shared facts → reflection boxes. Two weaknesses remain, and
they map onto exactly what a MIL jury (judging on impact, creativity, feasibility, relevance)
would poke at:

1. **No verifiable sources.** A Media & Information Literacy tool that asks users to trust
   hand-typed headlines with no way to check them quietly undercuts its own message. "Check the
   source" is the core MIL skill; right now there is nothing to click through to.
2. **The learner is handed the answer.** The product *tells* users why "invasion" differs from
   "special operation." They never perform the skill themselves, so there is no productive
   struggle and no payoff.

This iteration adds two features, credibility first:

- **Feature 1 — Verifiable provenance:** make every headline and every shared fact independently
  checkable, and be transparent about method.
- **Feature 2 — Predict-before-reveal:** make the learner *do* the skill (guess the outlet, spot
  the loaded word) before the explanation is revealed.

**Governing test (unchanged from 2.0):** *Does this feature help users understand why different
perspectives exist?* Both features pass — provenance models the "verify it yourself" habit, and
predict-before-reveal builds the recognition skill directly.

**Explicitly still the same product.** No live fetch, no LLM, no accounts, no new events. This is
additive to the existing three flagship dossiers (Russia–Ukraine 2022, TikTok Ban, Israel–Gaza).

---

## 2. Scope Decisions (locked)

| Decision | Choice |
| --- | --- |
| Priority | **Both, credibility first** — provenance, then the challenge layered on top. |
| Data reality | Headlines are treated as **verbatim-real and findable**; each must resolve to a real archived snapshot showing that exact headline. |
| Engagement mechanic | **Predict-before-reveal only.** No points, streaks, passport, or share-card. The reward is the insight. |
| Challenge gating | **Default, but skippable** — dossiers open in challenge mode with a visible "Just let me read →" skip. Never a dead end. |
| Challenge state | **In-session only** (React state). No `localStorage`, no forced re-guessing on scroll. |
| Link integrity | A headline that cannot be verified to a real snapshot is **fixed to a verifiable one, never faked**. |

## 3. Feature 1 — Verifiable Provenance

### 3.1 Per-source provenance footer
Each `SourceHeadline` card gains a footer line: `Outlet · Country · Publish date` plus a
**"Verify original ↗"** link that opens the archived snapshot (Wayback / archive.org) showing that
exact headline in a new tab. This models the MIL skill inside the product: don't trust us, check.

### 3.2 Sources & Method section
A new section placed **before the footer nav** on the event page:
- The full citation list for the dossier: per source, `Outlet — "headline" — publish date — link`.
- A 2–3 sentence **methodology note** (`Event.methodology`) explaining how framing terms were
  identified, that background facts are cross-checked against neutral records, and that MoliVerse
  does not tell users who is right. Transparency about method is itself a credibility signal.

### 3.3 Cited background facts
The "what everyone agrees on" block stops asserting facts bare. Each fact carries its own citation
(source label + link) rendered inline, so the shared floor is demonstrably verifiable.

---

## 4. Feature 2 — Predict-Before-Reveal

Section ① of the event page ("The same event, N headlines") becomes an **active challenge by
default**, with a visible **"Just let me read →"** skip and a **"Reveal all"** control.

Per headline, with the outlet hidden:

1. **Guess 1 — the voice.** "What kind of outlet wrote this?" → multiple choice drawn from the
   event's real orientations (e.g. Public broadcaster / State-owned / Pan-Arab / Private).
2. **Guess 2 — the framing.** "Tap the word doing the persuading." → the headline renders as
   tappable word/phrase chips; the correct answer is the source's contested word(s). Contested
   phrases (e.g. "special military operation") tokenize as a single tappable chip.
3. **Reveal.** The card flips to the full `SourceHeadline` (outlet, flag, orientation, tone,
   focus) + the provenance/verify link, plus a **non-judgmental insight line** — correct or not —
   e.g. *"Most readers see this as neutral too — notice how 'crisis' avoids naming anyone."* The
   reward is the aha, not a score.

**Behaviour details**
- Guessing is not mandatory to reveal (matches "default, but skippable"): a reveal action is
  always available on each card.
- "Just let me read →" reveals all sources at once and drops straight into the 2.0 passive scroll.
- State is in-session only; scrolling away and back does not force re-guessing.
- Tone stays MIL-neutral: wrong guesses are met with insight, never scolding.

## 5. Data Model Changes (`lib/types.ts`)

Additions to `Source`:
```ts
url: string;         // outlet's original article URL (attribution, even if link-rotted)
archiveUrl: string;  // Wayback/archive.org snapshot rendering the exact headline; opened by "Verify original"
publishDate: string; // "24 Feb 2022"
insight: string;     // non-judgmental reveal line shown after a guess (Feature 2)
```

Change `backgroundFacts` from `string[]` to typed, cited facts:
```ts
interface BackgroundFact {
  text: string;       // the source-neutral fact
  sourceLabel: string;// e.g. "UN General Assembly"
  url: string;        // citation link
}
// Event.backgroundFacts: BackgroundFact[]
```

Addition to `Event`:
```ts
methodology: string; // 2–3 sentence "how we made this" note for the Sources & Method section
```

No change to `ContestedTerm`, orientations, `timeline`, or `reflectionQuestions`. The challenge
reuses existing `orientation` and `contestedWords` / `framingWord` data.

**Data-integrity rules (extend §6 of 2.0):**
- Every source has non-empty `url`, a valid-URL `archiveUrl`, a `publishDate`, and an `insight`.
- Every `backgroundFact` has non-empty `text` and a valid-URL `url`.
- Every event has a non-empty `methodology`.
- Unchanged: `contestedWords` remain exact substrings of `headline`; `framingWord` maps to a
  `ContestedTerm.term`.
- Each `archiveUrl` is **manually confirmed during implementation** to resolve to a snapshot
  showing that exact headline; unverifiable headlines are replaced, not faked.

## 6. Components (`components/`)

| Component | Change | Responsibility |
| --- | --- | --- |
| `PerspectiveChallenge` | **New, client** | Wraps section ①. Holds per-source guess/reveal state in-session. Renders one `HeadlineGuess` per source; owns "Just let me read →" and "Reveal all". |
| `HeadlineGuess` | **New, client** | One headline: orientation multiple-choice + tap-a-word guess → on reveal renders `SourceHeadline` + insight line. |
| `SourceHeadline` | **Edit** | Add provenance footer (outlet · country · `publishDate` · "Verify original ↗" → `archiveUrl`). |
| `BackgroundFacts` | **Edit** | Render each `BackgroundFact` with its inline citation link. |
| `SourcesAndMethod` | **New, server** | Full citation list + `methodology` note; rendered before the footer nav. |
| `Highlight` | **Reuse** | Its substring logic powers the tap-a-word tokenizer (contested phrases = single chips). |

Server-by-default holds. Only `PerspectiveChallenge` / `HeadlineGuess` (plus existing
`SearchGallery`, `ReflectionPrompts`) are client components.

---

## 7. Data Flow

- Content stays **static typed data**; pages remain statically rendered. No runtime fetch, no API
  routes, no external network calls at request time. `archiveUrl` / `url` are plain outbound links
  the browser follows on click.
- **Challenge state** is React component state, in-session only. No persistence.
- Reflection answers continue to persist to `localStorage` per 2.0. Unchanged.

---

## 8. Error / Edge Handling

- **Reveal always available.** A user who guesses nothing can still reveal any card and continue.
- **Tap-a-word with an absent substring** → the tokenizer falls back to plain word chips and no
  chip is marked correct (never throws); a dev-time console warning is acceptable.
- **Missing/blank `archiveUrl` at build** → caught by the validation test (build fails), so a
  broken "Verify" link cannot ship.
- **Unknown slug, empty/no-match search, `localStorage` unavailable** → behave exactly as in 2.0.

---

## 9. Testing

- **Validation test (extend `lib/events/validate.ts` + `validate.test.ts`):** assert the new
  data-integrity rules in §5 for every event — source `url`/`archiveUrl`/`publishDate`, cited
  background facts, event `methodology` — alongside the existing 2.0 checks. Build fails on
  violation.
- **Word-tokenizer unit test:** contested phrases tokenize as single tappable chips; a tap maps to
  correct/incorrect against `contestedWords`; absent-substring falls back gracefully.
- **Manual smoke pass:** for each of the 3 dossiers — guess flow works (voice + word), reveal shows
  the full source + a resolving "Verify original" link, "Just let me read →" and "Reveal all"
  work, background facts show citations, Sources & Method renders with methodology.

Framework: the `vitest` setup added in 2.0.

## 10. Out of Scope (this iteration)

on the 2.0 roadmap.)
